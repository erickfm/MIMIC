## How to measure (conventions now in use)

- **Val loss:**
  - Command: `train.py --eval-only <ckpt> --seed 0 --batch-size 768 --data-dir data/mastfox_c9_half` (+ `--cond-heads` for cond models).
  - That's 100 batches from the 3 local val shards. Same seed and batch size make it exactly reproducible.
  - Never compare in-training val numbers across runs.
- **Proxy runs:** `tools/proxy_run.sh NAME MODEL DATA STEPS SEED [flags]` trains, averages the last 5 checkpoints, scores, and appends to `results.tsv`.
- **Sim h2h:**
  - Use `tools/sim_h2h.py`, bf16 (the default).
  - The fixed harness balances each template's orientation, gives every env the same game count and swaps policy order, so the game count rounds up to a multiple of 96.
  - With `--record-dir` it reports L-cancel and damage dealt.
  - An 8-point win-rate edge needs about 300 games. 96 games is a sanity check only.
- **Model names:** `fox-<size>-<data>-<steps>-<change>-<seed>`. Files on disk keep their run IDs (`p1-A-…`); the board shows both.

## Gotchas hit this session

- **`pkill -f <pattern>` kills its own shell** when the pattern is in the command line. Kill by PID.
- **The GPU is full while a proxy trains** (~20 GB). Evals and h2h need a gap: `kill -STOP <calib2 PID>`, wait for the current `proxy_run.sh` to exit, run, then `kill -CONT`. `checkpoints/proxy/gap1.sh` is a template.
- **The pod queue retries any unfinished run up to 3 times.** To stop a run, kill the queue script first, then torchrun, then start a new queue.
- **`sim_rl.py` must keep `CUBLAS_WORKSPACE_CONFIG=:0:0`.** Without it, cuBLAS faults after CUDA-graph rollouts. `CUDA_LAUNCH_BLOCKING=1` also hides the fault, but only by changing timing.
- **Production Dolphin inference is fp32.** Sim evals are bf16 by the owner's choice; the two measured even.
- **Uncommitted, deliberately:** `--help` and `manifests.json` in the repo root are strays from another session. Ask before deleting.
